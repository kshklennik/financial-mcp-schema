Financial MCP — canonical surface

1 · TOOLS — Model-invoked, parameterized, read-only. Data-access primitives only.
get_financial_attributes
unit (required) · readOnlyHint: true
Per Unit Type — Project: Unit & Hierarchy · Stream: Hierarchy · Customer/Program: Hierarchy
1. Annual budget for a unit. static{}: IT Gross Spent YTD (A), IT Gross Spend BOY (F), IT Gross Spend (A+F), Gross Investment Current CBA — keyed by Planview Work ID. dynamic{}: yearActuals, yearForecast — aggregated.
*16. aggregated:false must be in the payload. static{} is NOT rolled up child→parent; dynamic{} is. Ship the flag so the model can explain the gap.
static{} is null on a Stream. Return null, never 0 — and say which block is empty.
UNIT_NOT_SUPPORTED — same root cause as get_health_data / get_unit_risks.
get_unit_costs
unit (required) · from YYYY-MM · to YYYY-MM · breakdown: labor | other | both · granularity: month | cumulative
Merged: was get_labor_cost + get_other_costs. Stream/Project: Unit+Hierarchy · Customer/Program: Hierarchy
5–9. Unit costs. labor[]: per month/role/person = Hourly Rate × Workload × Working Hours. other[]: Cost Type incl. parent path, amount, comment. cumulative{}: past, current, forecast — per breakdown.
warnings[] is mandatory. Unmapped positions contribute 0. Return unmappedPositions: n.
UNIT_NOT_SUPPORTED — Resource Plan documented only down to account level.
get_rate_card
vendor · rateCardType · role · location · country · city · effectiveDate
all optional filters
Not unit-scoped — org-level access is an authorization check, not a level.
3. Rate card lookup — READ ONLY. Returns every match with hourly rate and effective period. Never collapse to one — Rate Card Type and Vendor change the number.
*15. No write tool, on purpose. Rate Cards are editable in DC by a Rates Editor. The tool must direct the user there.
get_working_hours_calendar
year (required) · country · vendor
Not unit-scoped — kept separate from get_rate_card to avoid disjoint required-param confusion.
4. Working hours calendar. hours + resolvedFrom: vendor+country | country | organizational | systemDefault. Always report which level answered.
Open decision: This resource does not exist in DC docs today — it is what the canonical shape needs.
2 · RESOURCES — Client-attached context. Small, stable, cacheable — read once, reused by every answer.
dc://dictionaries/cost-types
No params · URI-addressed · cacheable — Cost Category / Cost Type list
Correct category naming for free. Lets the model use exact configured labels instead of inventing them. Underpins *11 (what is out of scope).
Fixed, tiny, needed by nearly every financial answer. A tool call per question would be wasted round-trips.
dc://units/{unit}/hierarchy
URI template · param: unit · cacheable — Unit type + parents + children
Prevents the unsupported call. The model learns the unit type before calling, so it can say "not supported at Portfolio level" without a failed round-trip.
Design proposal. This resource does not exist in DC docs today.
3 · PROMPTS — User-invoked templates. Orchestration belongs here — never inside a tool.
compare_forecast_vs_actuals
args: unit, period · composition: get_unit_costs + get_financial_attributes
17. Compare RP forecast vs PV actuals. The template carries the three caveats: different breakdowns, different freshness, unmapped positions.
Planview side can only be annual static totals. The comparison is annual, not month-by-month.
budget_review
args: unit, period · composition: get_health_data + get_unit_risks + get_unit_costs
QBR / steering-committee prep. Each section keeps its own "as of" marker, since the feeds refresh on different schedules.
4 · RESPONSE & ERROR CONTRACT — Applies to every primitive above.
Typed nulls, never 0
Missing data returns null with a reason. Annual-feed blank→0 coercion happens upstream — label it as coerced, not a reported figure.
Provenance on every response
source feed + lastSyncedAt per block. Monthly and Annual sync independently — one response can mix two freshness dates.
Semantic errors, not empty results
PERMISSION_DENIED — name the missing role
UNIT_NOT_SUPPORTED
NO_DATA · OUT_OF_SCOPE · STALE
An empty array that reads as zero is the main risk.
readOnlyHint on all tools
No write tools. Rate Cards and Other Costs are editable in DC — the tool names the screen and the role instead (*15).
Explicit currency and unit
Every amount carries CAD. Every hours value carries its fallback level. *11: non-IT categories return OUT_OF_SCOPE, never an approximation.
Still not answerable
*12 freshness and *14 import-failure diagnosis need PV agent job status/logs — not exposed. *13 is handled by the null contract, not by a tool.

null vs 0 Null attribute values render as the literal string null — never 0. A null means the DC attribute is absent; 0 means a reported zero spend.

Date format — Java Date.toString() Effective dates use Java's default format: EEE MMM dd HH:mm:ss zzz yyyy e.g. Mon Jan 01 00:00:00 UTC 2026.
Never collapse to one Rate Card Type and Vendor independently change the rate. Every matching combination is a separate entry.
Filtering Case-insensitive partial-match on each param. Omit any to skip that filter.
active == true only Inactive rate cards are silently excluded. No warning emitted for them.
Validation errors — tool layer, before service is called
error: VALIDATION — unitId must not be blank. error: VALIDATION — invalid 'from' date format. Expected YYYY-MM, got: 2026/01 error: VALIDATION — invalid 'to' date format. Expected YYYY-MM, got: jan-2026 error: VALIDATION — breakdown must be 'labor', 'other', or 'both'. error: VALIDATION — granularity must be 'month' or 'cumulative'.
Semantic errors — service layer
error: NO_DATA — no budget data found for unit 002343_v1 in period 2026-01 to 2026-06. error: UNIT_NOT_SUPPORTED — unit type PORTFOLIO is not supported by this tool. error: PERMISSION_DENIED — missing role: FINANCE_VIEWER. error: SERVICE_UNAVAILABLE — downstream DC API returned 503. error: STALE — last sync was more than 24 hours ago. error: OUT_OF_SCOPE — cost category 'Marketing' is not an IT category.
Error format Always: error: <CODE> — <message>. Code is machine-readable; message is model-readable.
Validation is pre-service VALIDATION errors return from FinancialMcpTools before the service is called — format mismatches and blank IDs never reach the DC API.
Never an empty array for errors rate cards (0) is valid only when the query succeeds with no matches. Error states always produce a typed error string.
UNIT_NOT_SUPPORTED Returned when DC cannot resolve the unit or the unit type is unsupported. Same root cause as get_health_data / get_unit_risks limitations.
